# Fase 0 + Fase 1 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Estabilizar Studree (Fase 0) y pasar a la jerarquía de 3 niveles Carrera → Materia → Hoja, con un canvas de hojas conectadas por `[[links]]` (Fase 1).

**Architecture:** Supabase sigue siendo la fuente de verdad. La migración `0003` mueve las hojas a `subject_id` y deriva `sheet_links` del Markdown con triggers. La RPC `save_node_positions` guarda posiciones en lote. El cliente reutiliza `crudService` (ahora con paginación), un hook por pantalla y funciones puras en `lib/` para links, layout y export.

**Tech Stack:** React 18, Vite 5, JS + JSDoc, Tailwind 3.4, `@xyflow/react` 12, `@dagrejs/dagre`, TipTap 3 + `tiptap-markdown`, `@supabase/supabase-js` 2, `jszip`.

**Spec:** `docs/superpowers/specs/2026-10-14-diagnostico-fases-0-1-design.md`

## Global Constraints

- JavaScript con JSDoc, **sin TypeScript** (ADR-002). Tipar props y retornos.
- **Sin dependencias nuevas** (Mandamiento X).
- Colores y tamaños solo del design system (`tailwind.config.js`). Nada inventado.
- Los componentes no tocan `localStorage` ni Supabase: todo pasa por `services/`.
- Contrato de services: `{ data, error }`, con `error` como string en castellano.
- Markdown es la fuente de verdad del contenido (ADR-011). Los links se derivan de él.
- Cada cambio de código actualiza los docs correspondientes y `CHANGELOG.md` (Mandamientos III–V).
- Nada de secretos en `VITE_*`. El token de Management API solo se usa desde scripts locales.
- Commits en `rama-nicolas`, terminando con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Título con caracteres especiales** (`C++ (intro)`, `[x]`, `50%`): el rename y la resolución de links en SQL tienen que escapar la regex. Se cubre en el test SQL de la Task 1.
2. **Hoja que se enlaza a sí misma** (`[[Mi título]]` dentro de su propio contenido): no debe crear fila ni romper el `check`. Test SQL de la Task 1.
3. **Dos pestañas o dispositivos editando la misma hoja:** el borrador viejo no debe pisar el servidor. Lo cubre la lógica de `baseUpdatedAt` de la Task 3, verificada a mano.
4. **Headings dentro de bloques de código** en el export: no se corren de nivel. Script de la Task 7.
5. **Nombres de archivo repetidos** en el `.zip` (`Resumen`, `resumen`, `Resumen/`): se deduplican. Script de la Task 7.

- [ ] **Step 1: Escribir la migración**

```sql
-- 1. Hojas cuelgan de la materia
alter table sheets add column if not exists subject_id uuid references subjects(id) on delete cascade;
update sheets s set subject_id = u.subject_id
  from topics t join units u on u.id = t.unit_id
  where t.id = s.topic_id and s.subject_id is null;
alter table sheets alter column subject_id set not null;
alter table sheets alter column topic_id drop not null;
alter table sheets drop constraint if exists sheets_topic_id_fkey;
alter table sheets add constraint sheets_topic_id_fkey foreign key (topic_id) references topics(id) on delete set null;
alter table sheets add column if not exists pos_x double precision;
alter table sheets add column if not exists pos_y double precision;
create index if not exists sheets_subject_id_idx on sheets (subject_id);
create unique index if not exists sheets_subject_title_unique on sheets (subject_id, lower(trim(title)));

-- 2. updated_at de hojas solo si cambia título o contenido
drop trigger if exists sheets_set_updated_at on sheets;
create trigger sheets_set_updated_at before update on sheets for each row
  when (old.title is distinct from new.title or old.content_md is distinct from new.content_md)
  execute function set_updated_at();
```
