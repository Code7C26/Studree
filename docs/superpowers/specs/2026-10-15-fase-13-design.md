# Fase 13: papelera, adjuntos, plantillas e importar

> **Fecha:** 2026-10-15 · **Estado:** aprobado en el brainstorming, pendiente de revisión del spec
> **Rama:** a definir al implementar (se implementa **después** de que el rediseño visual esté
> commiteado, ver § 9) · **Versión objetivo:** 0.16.0 · **Migración:** `0006_fase13.sql`
> **Depende de:** rediseño visual (`2026-10-15-rediseno-visual-design.md`, ADR-018, 0.15.0).

## 1. Problema

1. Borrar una carrera, una materia o una hoja es **definitivo y a un click**: un error de dedo
   pierde apuntes sin vuelta atrás.
2. Las hojas solo tienen texto: no se puede guardar la **foto del pizarrón** ni el **PDF** de la
   clase junto a los apuntes.
3. Cada hoja nueva arranca en blanco aunque el estudiante siempre use la misma estructura
   (clase, resumen, práctica…).
4. No hay forma de **traer apuntes** de afuera (Obsidian, otros `.md`) ni de **restaurar un
   export** de Studree: el `.zip` exportado es de ida solamente.

## 2. Objetivo y criterios de éxito

- Borrar manda a una **papelera**; desde ahí se restaura o se borra para siempre. Lo que pasa
  **30 días** en la papelera se borra solo (adjuntos incluidos).
- Una hoja puede tener **adjuntos**: las imágenes se ven **dentro del texto** y todos los
  archivos se listan **al pie de la hoja**.
- "Nueva hoja" ofrece **plantillas**: 4 de fábrica y las que guarde el usuario.
- Se puede **importar** `.md` o `.zip` dentro de una materia, y **restaurar un export completo**
  de Studree (carreras, materias, hojas con su fecha y sus imágenes) desde el panel de carreras.
- El ciclo **exportar → importar** no pierde nada: el `.zip` exportado lleva los adjuntos.
- Los archivos de un usuario **no son accesibles** para nadie más (bucket privado + RLS).

**Fuera de alcance:** adjuntos en materias o carreras, papelera para adjuntos sueltos,
plantillas compartidas entre usuarios, importar desde Google Drive/Notion, edición de imágenes,
cuota de almacenamiento por usuario, Edge Functions.

## 4. Modelo de datos (`supabase/migrations/0006_fase13.sql`)

Idempotente, como la 0005. Funciones nuevas: **`security invoker`** (RLS aplica).

### 4.1 Papelera

```sql
alter table careers  add column if not exists deleted_at timestamptz;
alter table subjects add column if not exists deleted_at timestamptz;
alter table sheets   add column if not exists deleted_at timestamptz;
-- índices parciales: las lecturas normales piden "vivos"
create index if not exists careers_alive_idx  on careers  (user_id)    where deleted_at is null;
create index if not exists subjects_alive_idx on subjects (career_id)  where deleted_at is null;
create index if not exists sheets_trashed_idx on sheets   (deleted_at) where deleted_at is not null;
```

- **`trash_item(p_table text, p_id uuid) returns timestamptz`**: con un solo `now()` marca la
  fila y sus descendientes **vivos** (carrera → materias → hojas; materia → hojas). Whitelist de
  `p_table`: `careers`, `subjects`, `sheets`. Devuelve la marca (la usa "Deshacer").
- **`restore_item(p_table text, p_id uuid)`**: desmarca la fila y los descendientes que tengan
  **exactamente la misma** `deleted_at` (así una hoja borrada antes, por separado, no revive).
  Si un **ancestro** está en la papelera, se desmarca **solo ese ancestro** (no sus otros
  hijos): si no, lo restaurado quedaría invisible. Los hermanos que seguían marcados pasan a
  verse como elementos sueltos en la papelera.
- **`list_trash()`**: devuelve los elementos "de primer nivel" de la papelera (los que no tienen
  un padre marcado con la misma `deleted_at`), con:
  - `kind` (`career` | `subject` | `sheet`), `id`, `deleted_at`;
  - etiqueta: nombre (carrera/materia) o `created_at` + primer renglón (hoja);
  - ubicación: nombre de carrera / materia padre;
  - conteos de lo que arrastra: `subjects_count`, `sheets_count`, `attachments_count`.
- **`list_expired_trash()`**: devuelve los `(kind, id)` de primer nivel con
  `deleted_at < now() - interval '30 days'` y las `storage_path` de todos los adjuntos que
  cuelgan de ellos.

### 4.2 Adjuntos

```sql
create table if not exists attachments (
  id           uuid primary key default gen_random_uuid(),
  user_id      uuid not null default auth.uid() references auth.users(id) on delete cascade,
  sheet_id     uuid not null references sheets(id) on delete cascade,
  name         text not null check (length(trim(name)) between 1 and 200),
  mime_type    text not null,
  size_bytes   bigint not null check (size_bytes between 1 and 20971520), -- 20 MB
  storage_path text not null unique,
  created_at   timestamptz not null default now()
);
create index if not exists attachments_sheet_idx on attachments (sheet_id, created_at);
-- RLS: attachments_owner (for all to authenticated, auth.uid() = user_id), igual que la 0005
```

- **Sin `deleted_at` propio:** sigue a su hoja. La papelera muestra la hoja; al purgarla, la FK
  en cascada borra las filas.
- **Bucket `attachments`**, **privado**, `file_size_limit` 20 MB. Ruta:
  `<user_id>/<attachment_id>/<nombre-sanitizado>`.
- **Políticas de `storage.objects`** (select, insert, update, delete) para
  `bucket_id = 'attachments' and (storage.foldername(name))[1] = auth.uid()::text`.
- Se crea en la migración con `insert into storage.buckets … on conflict do nothing`.

### 4.3 Plantillas

```sql
create table if not exists sheet_templates (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null default auth.uid() references auth.users(id) on delete cascade,
  name       text not null check (length(trim(name)) between 1 and 60),
  content_md text not null check (length(content_md) between 1 and 20000),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
-- trigger set_updated_at (de la 0001) + RLS sheet_templates_owner
```

Las **de fábrica no van a la base**: viven en `src/constants/sheetTemplates.js` y no se borran.

### 4.4 Importar

Sin tablas nuevas. Las hojas importadas se crean con un `created_at` explícito (el original); la
columna ya lo permite (`default now()` solo aplica si no se manda).

## 5. Comportamiento

### 5.1 Papelera

- **Lecturas:** todo lo que lista carreras, materias u hojas filtra `deleted_at is null`:
  - `crudService` gana la opción `softDelete` (`true` en careers, subjects y sheets) que agrega
    `.is('deleted_at', null)` a `list`, `listByParents` y `get`;
  - `home.service.getLastEditedSheet` y `sheetsService.searchContent` también filtran;
  - las correlativas de una materia en la papelera **no se borran**; el canvas de carrera ya
    solo dibuja las que unen materias visibles.
- **Borrar** (carrera, materia u hoja) llama a `trash_item` en vez de `delete`. El
  `ConfirmDialog` dice "Se mueve a la papelera" (sin "no se puede deshacer"); después aparece un
  aviso con **Deshacer** (`restore_item`), con el mismo patrón que el borrado de notas del Inicio.
- **Hoja de la carpeta:** antes de mandarla a la papelera se cancela su autosave pendiente
  (regla existente de la Carpeta).
- **Página `/papelera`** (dentro del workspace; entrada al pie del explorador):
  - lista de `list_trash()`, lo más reciente arriba;
  - cada fila: ícono del tipo, etiqueta, ubicación, "incluye 4 materias, 23 hojas",
    "se borra en N días", **Restaurar** y **Borrar para siempre** (con confirmación);
  - arriba: **Vaciar papelera** (con confirmación); estado vacío: "La papelera está vacía".
- **Borrar para siempre / Vaciar / purga:** el mismo camino en `trash.service`:
  1. juntar las `storage_path` de los adjuntos afectados;
  2. borrarlas con `storage.from('attachments').remove(paths)` (de a 1000);
  3. `delete` de las filas de primer nivel (la cascada borra hijos y `attachments`).
  Si falla el paso 2 no se hace el 3 (se reintenta la próxima vez; nunca quedan filas apuntando
  a archivos borrados, a lo sumo archivos sin fila un rato).
- **Purga automática:** una vez por sesión, al tener usuario (`AuthProvider`), en segundo plano
  y sin bloquear la UI: `list_expired_trash()` → pasos 2 y 3. Los errores solo van a la consola.

### 5.2 Adjuntos

- **Subir:** arrastrar o pegar un archivo sobre una hoja, o el botón de adjuntar (ícono clip) de
  la cápsula de herramientas. Hasta 20 MB; más grande → aviso y no se sube.
  1. `attachments.service.upload(sheetId, file)`: genera el id, sube a Storage y recién después
     inserta la fila; si la fila falla, borra el archivo.
  2. Mientras sube, en la posición del cursor queda un marcador "Subiendo nombre…" (decoración,
     no entra en el Markdown).
  3. Al terminar se inserta `![nombre](adjunto:<id>)` si es imagen (`image/*`) o
     `[nombre](adjunto:<id>)` si no.
- **Hoja nueva sin guardar:** una hoja vacía no existe en la base todavía. Si se adjunta algo a
  una hoja nueva, primero se crea la hoja (ya tiene contenido: el adjunto) y después se sube.
- **Ver:** una extensión de imagen propia (sobre `@tiptap/extension-image`) guarda `src`
  `adjunto:<id>` en el documento (así el Markdown no cambia) y en la vista lo resuelve a un
  **link firmado** (`createSignedUrl`, 1 h, cacheado por id en memoria). Si el adjunto no existe
  → recuadro "Adjunto no disponible".
- **Links `adjunto:`:** la extensión `link` acepta el protocolo `adjunto`; el click abre el
  archivo con un link firmado en una pestaña nueva.
- **Lista al pie de la hoja:** "Adjuntos (N)" debajo del papel (solo si hay alguno): nombre,
  tamaño legible, **Abrir** y **Borrar** (con confirmación). Borrar un adjunto es **definitivo**
  (archivo + fila); su referencia en el texto queda como "Adjunto no disponible".
- **Huérfanos:** sacar una imagen del texto **no** borra el archivo (pudo ser sin querer); sigue
  en la lista al pie.
- **Seguridad:** el nombre del archivo se sanitiza para la ruta; el `mime_type` sale del
  navegador y solo decide imagen o link (el contenido nunca se ejecuta: las imágenes van en
  `<img>`, el resto se descarga). Markdown sigue con `html: false`.

### 5.3 Plantillas

- **De fábrica** (`constants/sheetTemplates.js`): **Clase**, **Resumen**, **Práctica**,
  **Repaso para parcial**. Cada una es Markdown corto con headings que el usuario reemplaza:

  | Plantilla | Contenido |
  |-----------|-----------|
  | Clase | `# Clase` · `## Conceptos clave` · `## Ejemplos` · `## Dudas para preguntar` |
  | Resumen | `# Resumen` · `## Idea principal` · `## Puntos clave` · `## Para recordar` |
  | Práctica | `# Práctica` · `## Ejercicio 1` (Enunciado / Resolución) · `## Errores que cometí` |
  | Repaso para parcial | `# Repaso` · `## Temas que entran` (lista de tareas) · `## Fórmulas y definiciones` · `## Preguntas de práctica` |

- **"Nueva hoja"** pasa a botón partido: el click principal crea en blanco (como hoy); la flecha
  abre un menú con las de fábrica, las del usuario y "Administrar plantillas…".
- Una hoja creada **desde una plantilla se guarda al crearse** (ya tiene contenido; la regla
  "una hoja vacía no se guarda" sigue intacta).
- **"Guardar como plantilla"** en el menú de cada hoja: pide el nombre (`PromptDialog`) y guarda
  su `content_md` actual. Las referencias `adjunto:` se **quitan** del contenido guardado (una
  plantilla no arrastra archivos de otra hoja).
- **"Administrar plantillas"**: modal con las del usuario: renombrar, editar el texto
  (textarea de Markdown) y borrar (con confirmación; definitivo, no va a la papelera).

### 5.4 Importar

Todo el parseo vive en `lib/import/` (puro, sin React ni Supabase, con tests); la escritura en
`import.service`. `jszip` ya es dependencia y se carga con `import()` dinámico, como en el export.

- **En una materia** (botón "Importar" junto a "Exportar"): acepta uno o varios `.md`, o un
  `.zip`. Cada `.md` → una hoja de **esa** materia (se ignora la estructura de carpetas del zip).
- **En el panel de carreras** (botón "Importar" junto a "Exportar todo"): acepta un `.zip`.
  - Carpeta `Carrera/Materia/archivo.md` (y la variante con `Studree/` arriba, de "Exportar
    todo") → recrea carreras y materias. Si el frontmatter trae `carrera:`/`materia:`, mandan.
  - Si ya existe una carrera **viva** con el mismo nombre (sin distinguir mayúsculas), se usa;
    lo mismo con la materia dentro de esa carrera. Si no, se crean (color por defecto de la
    paleta, sin correlativas).
  - Un `.md` sin carpeta suficiente (por ejemplo en la raíz) va a una carrera "Importado" /
    materia "Importado".
- **Por cada `.md`:**
  - se quita el frontmatter del contenido;
  - fecha (`created_at`): `creada:` del frontmatter → nombre `AAAA-MM-DD HH-MM` → fecha de
    modificación del archivo dentro del zip → ahora;
  - un `.md` vacío (sin texto tras quitar el frontmatter) se saltea;
  - **duplicados:** si en la materia destino ya hay una hoja viva con el mismo `created_at`
    (al minuto) y el mismo contenido, se saltea. Importar dos veces el mismo zip no duplica.
- **Imágenes y archivos del zip:** las referencias `![…](ruta)`, `[…](ruta)` a archivos del
  zip (ruta relativa al `.md`) y `![[archivo]]` de Obsidian (por nombre, en cualquier carpeta)
  se suben como adjuntos de la hoja y la referencia se reescribe a `adjunto:<id>`. Lo que no se
  encuentra queda como está. Archivos de más de 20 MB → se saltean y van al informe.
- **Flujo:** elegir archivos → **resumen previo** ("Se van a crear 2 carreras, 5 materias,
  40 hojas y 12 adjuntos; 3 hojas ya existen y se saltean") → **Importar** → barra de progreso
  → **informe** con lo que no se pudo importar (archivos que no son `.md`, demasiado grandes,
  errores de red). Lo ya importado queda importado aunque algo falle a mitad.

### 5.5 Export (cambio para cerrar el ciclo)

- **`.zip`:** cada materia con adjuntos lleva una carpeta `adjuntos/` con los archivos
  (deduplicados con `uniqueName`) y en el `.md` las referencias `adjunto:<id>` pasan a la ruta
  relativa `adjuntos/<nombre>`. Así Obsidian las ve y el import las reconoce.
- **`.md` único y "Copiar para IA":** no llevan archivos; `![nombre](adjunto:<id>)` pasa a
  `[imagen: nombre]` y `[nombre](adjunto:<id>)` a `[archivo: nombre]`.
- Lo que está en la papelera **no** se exporta.

## 6. Diseño visual (ADR-018)

Todo lo nuevo sigue el rediseño "lámpara":

- Paneles, modales y menús nuevos en `.glass`; la papelera es una lista sobre `bg` con filas
  sobrias (no tarjetas idénticas con la misma sombra).
- Íconos SVG en `src/components/ui/Icon.jsx` (stroke 1.75, `aria-hidden` si son decorativos,
  `aria-label` en botones solo-ícono). Se suman: `trash`, `restore`, `paperclip`, `upload`,
  `download`, `template`, `chevron-down`, `image`. Sin emojis como íconos.
- Lista "Adjuntos" al pie de la hoja: sobre el papel crema (`ink`, `ink-muted`,
  `paper-border`), no en vidrio.
- Imágenes en el editor: ancho máximo de la columna del papel, radio `rounded-md`, borde
  `paper-border`; "Adjunto no disponible" en `ink-muted` con borde punteado.
- Etiquetas en minúscula normal, sin MAYÚSCULAS, sin cadenas "A · B · C". Foco visible en todo.
  Sin animaciones de entrada; la barra de progreso del import es la única animación nueva y
  respeta `prefers-reduced-motion`.
- Colores solo del design system (`tailwind.config.js`); el color de la materia por
  `--subject-*` donde corresponda.

## 11. Riesgos

- **Espacio:** el plan gratuito de Supabase da 1 GB de Storage. Con 20 MB por archivo se llena
  con ~50 PDFs grandes. Se documenta; la cuota por usuario queda fuera de alcance.
- **Purga sin servidor:** si el usuario no entra en meses, lo vencido espera (no se ve, solo
  ocupa espacio).
- **`link` y el protocolo `adjunto:`:** la extensión de TipTap valida protocolos; hay que
  registrar `adjunto` o el link se descarta al pegar. Se verifica al empezar los adjuntos.
- **`tiptap-markdown` e imágenes:** hay que confirmar que serializa `![alt](adjunto:id)` sin
  escapar el `src`. Si no, se ajusta en `lib/markdown/serialize.js` (como los `[[links]]`).
- **Zips grandes:** se procesan en el navegador; un zip de cientos de MB puede ser lento. El
  resumen previo muestra el tamaño y la barra de progreso evita que parezca colgado.
- **Hojas con muchas imágenes** firman una URL por imagen: se cachean 1 h por id y se piden en
  paralelo solo para las hojas montadas.
